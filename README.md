# YouTube Chess Search

Search a collection of Daniel Naroditsky's YouTube videos for moments that show a chess position. Play moves from the starting position on the board, then browse matching moments by video and timestamp. Opening a result takes you to that moment in the YouTube video.

The search runs in the browser against the channel data bundled with the site. It does not call a search API, so the site can be hosted as a static GitHub Pages site.

## Run locally

```sh
npm ci
npm start
```

## Update the channel data

The app reads `src/data/combined-positions.json`, generated by the formatter as a channel-data JSON document. To refresh the search index, replace that file with the formatter's new `combined-positions.json` output, then run the app:

```sh
npm start
```

Commit the updated data file with the app change. GitHub Pages serves the static build, so an update becomes available after the Pages workflow builds and deploys the new commit; replacing a local file does not update an already deployed site.

## GitHub Pages

The `main` branch workflow runs the Angular tests, builds the app, and deploys it to GitHub Pages. The repository is published beneath `/yt-chess-search/`, so the build uses `/yt-chess-search/` as its base href. If the repository name or hosting path changes, update the `--base-href` value in `.github/workflows/deploy.yml` to match the new path.

The built site and its JSON data are static assets. Searches happen locally in the browser, and a deployment does not require a server or database.
